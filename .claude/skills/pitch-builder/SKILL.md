# Pitch builder

Presentation is one of five equally weighted criteria, and global judges only see the project page and the demo link. Treat the video as a deliverable.

## Inputs

`work/spec.md`, `docs/judging.md`, `docs/rules.md`. On Sunday, also the deployed URL and screenshots.

## 1. 30-second video (preferred demo)

Follow the official beat sheet exactly. Spoken words: about 70-80 words in total.

| Time | Beat | Content |
|---|---|---|
| 0:00-0:02 | Team | Team name, where we are (Paris) |
| 0:02-0:05 | Challenge | Challenge name + the inspiration in one line |
| 0:05-0:10 | Title | Project name + tagline |
| 0:10-0:20 | How it works | The product on screen + which NASA data powers it |
| 0:20-0:30 | Impact | Who benefits, at what scale, what's next |

Produce:
- the voice-over script with timings and word count;
- a shot list (what's on screen each second; real product footage, not slides);
- English subtitles (SRT) if the voice-over isn't in English;
- a checklist: ≤ 30.0 s total, English subtitles, no NASA logos, AI-generated visuals watermarked, no minors, music licence OK.

## 2. 7-slide fallback

Max 7 slides including the title. Suggested: 1 title (team, members, challenge) · 2 problem and user · 3 solution screenshot · 4 how it works + NASA data · 5 validity (method, results) · 6 impact · 7 next steps. Low word counts, large visuals.

## 3. Live local pitch (Paris judges)

Ask the user for the time limit the local organisers set (historically ~4 minutes on site). Structure: hook → user and problem → live demo of the core flow → data and validity → impact → ask. Prepare answers to the 5 most likely judge questions (science validity, data limits, what's novel, who'd use it, what's next).

## Output

Write `work/pitch.md` from `templates/pitch-30s.md` and `templates/slides-7.md`. Flag every line that is a claim needing evidence.
